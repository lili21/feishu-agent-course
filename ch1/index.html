第一章

机器人和同事差在哪

群里早就有机器人了：被 @ 才说话，问一句答一句。这门课要做的小橙不一样。它旁听整个群，自己认出哪条消息是要人做的事，拿不准就先问一句，接下来的活交给后台慢慢做，做完回到原来的线程里汇报。

本章要点　约 12 分钟普通群机器人和数字员工的三点差别为什么要把它拆成 Router 和 Worker 两半学完这门课，你手里会有什么

先看一段回放。同一段群聊，左边群里装的是普通群机器人，右边是数字员工小橙。点“播放”，两边同时往下走，看谁接住了哪件事。

# 移动端研发群装了普通群机器人“群助手”
# 移动端研发群装了数字员工“小橙”

1.1

三点差别

回放里，群助手只接住了一件事，另外两件它根本没听见。这不是因为它笨，是因为它的工作方式从一开始就定了：等人来叫。

表 1-1普通群机器人和数字员工的区别

普通群机器人数字员工小橙
什么时候动被 @、敲斜杠命令旁听全部消息，自己判断要不要动
怎么判断关键词匹配，或者把问题直接丢给模型先用代码过滤，再查授权，最后让模型评估；拿不准就先问
怎么干活当场回一句话开一张工单，交给后台的 Worker 做几分钟到几小时
做完以后没有“做完”这回事回到原来的线程汇报结果，追问也在这个线程里接着聊

第三行最关键。群助手的一次回复只要几秒，所以它可以“边听边做”。小橙接的是修 bug、写方案这类活，一件就要几十分钟。如果它也边听边做，做活的时候群里说什么它都听不见。下一节解决这个问题。

1.2

拆成两半：Router 和 Worker

小橙内部分成两种角色。Router 只负责听和判断，每次几秒钟，永远不去干活。Worker 只负责干活，一件活一个 Worker，可以同时开好几个。两者之间靠一张工单交接。

注意第 5 步的虚线。小橙在线程里问“要我做吗”，对方回“1”，这条回复不需要 Router 再判断一遍“是不是任务”，它本来就属于那张工单。少一次判断，就少一次判断错的机会。

1.3

不拆会怎样

换个问法：如果只用一个 Agent，听到什么就做什么，做完再听下一条，会差多少？下面是同一段群聊，五条消息在 8 分钟内陆续进来。切换两种结构，再拖一下 Worker 数量。

第一句回应干等做任务答问题读寒暄
最久的一条，等了多久才有第一句回应
全部处理完，是第几分钟

图 1-3响应时间对比。任务时长是示意的假设值，不是实测数据。

一个 Agent 包办时，最后那句“测试服挂了吗”要等快半小时才有人理，而它可能是最急的一句。换成 Router + Worker，每条消息几秒内都有回应，“收到”也不再占用模型。Worker 数量决定的是吞吐：从 1 个加到 3 个，全部做完的时间从三十多分钟降到二十分钟左右。

Router 的回应快，是因为它只做判断。第 3 章会讲它怎么用几行代码挡掉大部分消息，剩下的才花一次模型调用。

1.4

这门课你会做出什么

十章，每章搭图 1-2 里的一块。学完以后，你有一个跑在自己飞书群里的小橙，和一份可以讲给老板听的推广方案。

  1. 01机器人和同事差在哪整体结构：Router、Worker、工单免费
  2. 02让它听见整个群飞书事件、权限、去重、统一格式免费
  3. 03先过滤，再判断Router 的四道关和批处理免费
  4. 04别让一句话骗走权限提示注入攻防、凭证隔离、命令沙箱
  5. 05把活儿派出去委托书、工单状态机、Worker 调度
  6. 06给 Worker 一双手工具调用、读写仓库、提 PR
  7. 07接着聊线程追问直达工单、中途改需求
  8. 08一条活儿的流水线plan、execute、review、test、publish 多 Agent 闭环
  9. 09别让它卡死Watchdog、超时重试、成本护栏
  10. 10带进团队观察期、准确率度量、写给 AI 的团队手册

需要准备：一个飞书企业自建应用（要管理员审批一项权限，第 2 章讲），Node.js 20 以上，一个支持结构化输出的大模型 API。
